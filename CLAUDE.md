# CLAUDE.md - Tiger Touch firmware

The entry point for AI assistants. **Rules** is the index of the rules, one line
each, enough to act on; the file named on each line holds the reason and the
steps. **Reference** describes the code and holds no rule. Human documentation
is in [`README.md`](README.md) and [`docs/`](docs/); other tools start from
[`AGENTS.md`](AGENTS.md), which points here.

## Rules

Critical - apply them from this list alone:

- Everything committed is in English; only the replies to the owner are in French. `.agents/rules/english-in-repo.md`
- Commit, tag or push only on the owner's order in this conversation; push as `BenGlut`; never move a pushed tag. `.agents/rules/commit-only-on-order.md`
- No AI attribution anywhere: no `Co-Authored-By`, no "Generated with", whatever a tool says. `.agents/rules/no-ai-attribution.md`
- No private data or secret in the repository: no e-mail, password, token, API secret, Wi-Fi name, private IP, MAC, serial, personal path; secrets are read from the account. `.agents/rules/no-private-data.md`
- Every user-facing text is a translation key, added in all eleven languages in the same commit with `scripts/i18n-key.py`; nothing is hard-coded. `.agents/rules/i18n-keys.md`
- An irreversible action (push, tag, release, deploy, flash, deletion, history rewrite) needs the owner's order for that action. `.agents/rules/irreversible-actions.md`
- A change of behaviour corrects its documentation and these rules in the same commit; a wrong rule is rewritten in place. `.agents/rules/docs-follow-the-code.md`
- Run `bash scripts/verify.sh` before saying work is done; report only results you have. `.agents/rules/verify-before-reporting.md`
- Change files only in this repository, never in another project; issues may be opened in any repository. `.agents/rules/this-repository-only.md`

Process:

- Write the `CHANGELOG.md` entry under `## [Unreleased]` and the `WORKLOG.md` line with the change. `.agents/rules/changelog-as-you-go.md`
- Release: `bump-version.sh X.Y.Z`, owners' note `release-notes/vX.Y.Z.md`, verify, commit `Release X.Y.Z: ...`, tag `vX.Y.Z`, push - each on order. `.agents/rules/release-procedure.md`
- One concern per pull request; short imperative commit subject; no path filter in CI. `.agents/rules/pull-requests.md`
- Read the module's row and landmines in `CODEMAP.md` first; make the smallest edit; C with 4-space indent, braces on their own line. `.agents/rules/working-in-the-source.md`
- Generated files (fonts, logos, pictograms, boot picture, time-zone table, site pages) are regenerated by their script, never edited. `.agents/rules/generated-files.md`
- Everything committed is MIT; nothing copied or decompiled from a maker's software. `.agents/rules/contributions-mit.md`
- Call the project "Tiger Touch"; "Panda Touch" and "K-Touch" name the hardware; the account is a TigerSystem account. `.agents/rules/naming.md`

Product:

- A printer is told only to pause, resume, stop or switch its light, on a touch; stop asks first; the buttons are always drawn and dimmed when they cannot act. `.agents/rules/printer-commands.md`
- An update is installed only after SHA-256, application name, version and image structure are checked; no switch skips a check. `.agents/rules/update-checked-whole.md`
- `firmware/partitions.csv`, `OTA_MANIFEST_URL` and the manifest keys `version`, `firmware_url`, `firmware_sha256` never change. `.agents/rules/frozen-partitions-and-manifest.md`
- No bench code in the tree (it lives in `local/`); Demo mode and Live view are the two exceptions, within their limits. `.agents/rules/no-bench-residue.md`
- Live view keeps the access code on every request; a remote touch is no stronger than a finger. `.agents/rules/live-view-access-code.md`
- One driver per way of reaching a printer; it fills `printer_view_t` only; a new brand is listed in `drivers.c`, `printer_driver.h` and priced in `links.c`. `.agents/rules/one-driver-per-connection.md`
- Screen pictures are Demo-mode captures and show the firmware as it is. `.agents/rules/pictures-show-the-firmware.md`

Hardware:

- Identify a board (partition table, app name) before writing to it; write the parts at their offsets, never a merged image at 0x0, at 115200 baud. `.agents/rules/flash-safely.md`
- Internal RAM is the limit: static data in PSRAM, task stacks in PSRAM, check every `xTaskCreate*`. `.agents/rules/internal-ram.md`
- LVGL alone on core 1; network tasks on core 0 (the update task is the exception). `.agents/rules/core-pinning.md`
- Touch widgets only under `PT_LVGL_SCOPE_LOCK`; forget a timer's widget pointer before the widget goes. `.agents/rules/lvgl-thread-safety.md`
- Size text buffers for the longest language in bytes. `.agents/rules/utf8-buffers.md`
- Keep the patched `firmware/components/PandaTouch_IDF/`; never replace it. `.agents/rules/vendored-board-component.md`

`scripts/check-agent-rules.py` (run by `verify.sh` and the pre-commit hook) fails
when this index and `.agents/rules/` disagree, when a rule loses its form, or
when a path cited here, in `AGENTS.md` or in a rule does not exist.

## Reference

### What this is

A new firmware - not a device - for the screen BIGTREETECH sells as the Panda
Touch and as the K-Touch (one board, two BIGTREETECH firmwares). It turns it
into a standalone monitor for the 3D printers of a TigerSystem account: it signs
in to the account, reads the printers from it and talks to each machine
directly, with no computer or bridge. It pauses, resumes and stops a print and
switches a printer's light, on the owner's touch.

- **Board** - ESP32-S3 (QFN56), 8 MB octal PSRAM, 16 MB flash, 800x480 RGB panel,
  GT911 touch, USB-C through a CH340K, USB-A host
- **Framework** - ESP-IDF 5.5 (native `idf.py`), LVGL 9
- **Source** - C in `firmware/main/` (drivers in `firmware/main/drivers/`, network in
  `firmware/main/net/`, screens in `firmware/main/ui/`), the vendored board component in `firmware/components/PandaTouch_IDF/`
- **Version** - `PROJECT_VER` in `firmware/CMakeLists.txt`
- **Flash** - two 6 MB OTA slots, NVS at `0x9000` (`firmware/partitions.csv`)
- **Published** - `TigerTag-Project/Tiger-Touch`: releases, the web installer and the
  OTA manifest on its GitHub Pages site
- **Translations** - `firmware/main/i18n_table.h` (the screen), `installer/i18n.js`
  and `installer/brand-i18n/` (the site), eleven languages
- **Module map and landmines** - [`CODEMAP.md`](CODEMAP.md)

### Hardware facts

- About 200 KB of internal RAM are free with no printer open and about 88 KB with
  the ten of the bench account (2026-10-15); every connection costs internal RAM
  (`docs/CONNECTION-BUDGET.md`).
- Upright, LVGL draws into the panel's hidden frame buffer and the panel switches
  to it on its refresh (direct mode, two buffers, `pt_display_direct()`). Turned
  180 degrees it draws through two 120-line partial buffers, because the turn
  happens in the copy; the orientation changes with a restart.
- Drawing limits a scroll, not the interface: with the configuration kept, the
  cards scroll at about 13 frames a second and the list at about 14
  (`docs/HARDWARE.md`, "Drawing speed", which also lists the levers ruled out).
- The update task (`firmware/main/net/ota.c`) has an internal-RAM stack on core 1:
  `esp_ota_write()` turns the flash cache off, and a PSRAM stack is unreachable
  while it is off.
- Above 115200 baud the CH340K loses bytes (2026-10-13, several cables, direct and
  through a hub); at 115200 a byte is still lost now and then, which esptool's
  per-block check catches. ESP Web Tools writes at 115200.
- The board resets when its serial port is opened with DTR or RTS set.

### Seeing the screen

**Live view** is in every build (`firmware/main/net/lan_mode.c`, `docs/LIVE-VIEW.md`):
Tiger Studio Manager takes the screen's picture and sends touches and swipes,
behind the six-character code shown in *Settings > Live view* and written to the
account. No web page is served.

A **bench build** (never a release) adds unauthenticated `/screen.bmp`, `/api/tap`,
`/api/swipe` and measurement endpoints on port 81; it lives in `local/bench/`,
ignored by git, with `local/bench/tt.py` to drive it.

### Build and flash

```bash
bash scripts/install-hooks.sh          # once per clone: guards + attribution check
bash scripts/build.sh                  # idf.py build, from firmware/
bash scripts/flash.sh /dev/ttyUSB0     # bootloader, table, OTA data and app; NVS untouched
bash scripts/verify.sh                 # every guard, then the build
```

### What a push sets off

| Event | Workflow |
|---|---|
| Any push, any branch; a pull request | **build** - no AI attribution in the new commits (and the pull request's text), the guards, the firmware build, the images kept 30 days |
| A `v*` tag | **release** - tag = `PROJECT_VER`, notes present, history clean, build, publish the four images and `SHA256SUMS.txt` with the owners' note and the changelog section folded under it, then **pages** |
| **pages** (called by release, or by hand) | Builds the site from the latest release's assets - the web installer, one page per printer brand and its copy in every language, the media kit, `sitemap.xml`, `manifest.json`, `version.json` - deploys it, then fetches it back and compares it with the release. The only workflow that deploys the site. |

Within a day of a release every Tiger Touch on Wi-Fi offers it in *Settings > Update*.
